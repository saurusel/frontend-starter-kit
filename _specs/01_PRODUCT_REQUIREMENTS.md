# Product Requirements — frontend-starter-kit

## 1. Назначение проекта

`frontend-starter-kit` — базовый frontend-шаблон для хакатонов, быстрых MVP и внутренних прототипов.

Он должен позволять команде быстро стартовать новый проект без ручной настройки архитектуры, роутинга, авторизации, ролей, темы, PWA, UI-kit, таблиц, форм, графиков и API-слоя.

## 2. Что проект НЕ должен делать

Проект не должен становиться полноценной CRM, ERP, таск-трекером или аналитической системой.

Все доменные сущности являются демонстрационными.

Используемые сущности:

- пользователи;
- проекты;
- заявки;
- задачи;
- команды;
- аналитика;
- события активности;
- уведомления.

## 3. Основной сценарий использования

1. Команда клонирует проект.
2. Устанавливает зависимости.
3. Запускает dev-сервер.
4. Открывает `/ui-kit`, `/tables`, `/forms`, `/panels`, `/charts`.
5. Копирует нужные паттерны в рабочие фичи.
6. Меняет моковые сущности на реальные API.
7. Использует готовую авторизацию, роли и PWA как основу.

## 4. Обязательные страницы

### `/login`

- форма логина;
- выбор роли;
- быстрые кнопки входа;
- моковые пользователи;
- validation;
- отображение ошибок;
- redirect после входа.

### `/dashboard`

- KPI-карточки;
- графики;
- последние события;
- быстрые действия;
- переключение периода;
- loading/error/empty states.

### `/tables`

- таблица с поиском;
- фильтры;
- сортировка;
- пагинация;
- выбор строк;
- bulk actions;
- row actions;
- открытие правой панели;
- состояния загрузки, ошибки и пустого списка.

### `/charts`

- line chart;
- bar chart;
- area chart;
- pie/donut chart;
- chart card;
- period switcher;
- empty chart state;
- loading chart state;
- dark theme compatibility.

### `/forms`

- базовая форма;
- форма с разными типами полей;
- форма в dialog;
- форма в side panel;
- validation через zod;
- server error state;
- dirty state;
- unsaved changes warning.

### `/panels`

- обычная правая панель;
- закрепляемая правая панель;
- панель просмотра;
- панель редактирования;
- панель со сменой выбранного элемента;
- панель с шагами;
- loading/error/empty;
- предупреждение о несохранённых изменениях.

### `/ui-kit`

- базовые компоненты;
- составные компоненты;
- layout-компоненты;
- состояния;
- паттерны использования;
- краткое описание каждого компонента.

### `/settings`

- переключение темы;
- профиль;
- уведомления;
- пример формы сохранения;
- optimistic update;
- toast после сохранения.

### `/access-denied`

Страница отказа в доступе.

### `/not-found`

404-страница.

## 5. Главные UI-паттерны

Обязательно показать:

- AppShell;
- Sidebar;
- Header;
- Theme Toggle;
- User Menu;
- Data Table;
- Filters;
- Search;
- Row Actions;
- Bulk Actions;
- Confirm Dialog;
- Details Panel;
- Form in Dialog;
- Form in Side Panel;
- Charts;
- Empty State;
- Error State;
- Loading State;
- Offline State;
- Access Denied State.

## 6. PWA

Минимальные требования:

- manifest;
- service worker;
- иконки;
- возможность установки;
- offline screen;
- уведомление о доступной новой версии;
- корректный production build.

## 7. Storybook

Storybook обязателен.

Истории нужны для:

- базовых UI-компонентов;
- составных компонентов;
- состояний;
- таблицы;
- формы;
- панели;
- карточек метрик.

## 8. Язык

Весь UI — на русском.

Код, названия файлов, переменных и компонентов — на английском.

## 9. Критерии успеха

Проект успешен, если:

- его можно использовать как стартовый шаблон;
- его можно использовать как UI-kit;
- его можно использовать как учебный пример;
- его можно быстро адаптировать под хакатон;
- команда понимает, куда добавлять страницы, фичи, сущности и компоненты.
